# Архитектура BOGELIKA Platform

## Общая схема

```text
Мастер
    │
    ▼
Telegram
    │
    ▼
n8n
    │
    ▼
Data Tables
    │
    ├────────► Google Sheets
    │
    ├────────► Google Drive
    │
    ├────────► WorkClient
    │
    └────────► AI
```

---

## Telegram

Используется мастерами для отправки отчётов.

---

## n8n

Основной движок автоматизации.

Отвечает за:

- управление логикой
- обработку фотографий
- проверку текста
- сохранение данных
- интеграции

---

## Data Tables

Техническая база проекта.

Хранит:

- активные сессии
- части альбомов
- готовые отчёты

---

## Google Sheets

Рабочая таблица управляющих.

Используется для просмотра отчётов.

---

## Google Drive

Хранение фотографий.

Каждый отчёт получает собственную папку.

---

## WorkClient

Планируется автоматическое добавление информации в комментарий к записи клиента.

---

## AI

Используется для анализа текста и фотографий.

---

## Принцип

Все данные сначала сохраняются в технической базе.

После этого экспортируются во внешние сервисы.

Это исключает потерю данных при временных сбоях.

## Омниканальная архитектура

Telegram, MAX и ВКонтакте являются только каналами взаимодействия с пользователями

После получения сообщения данные должны преобразовываться в единый внутренний формат

Пример внутреннего события:

```json
{
  "channel": "telegram",
  "external_user_id": "123456",
  "external_chat_id": "123456",
  "message_type": "photo",
  "text": "",
  "file_ids": [],
  "received_at": "2026-07-15T12:00:00Z"
}
