# BOGELIKA Platform

## Описание проекта

BOGELIKA Platform — система автоматизации процессов сети студий красоты «БОГЕЛИКА»

Текущий основной модуль — Telegram-бот для приёма и обработки отчётов мастеров по выполненным процедурам

Цель проекта — сократить ручную работу мастеров, администраторов, управляющих и собственника с помощью автоматизации и искусственного интеллекта

---

## Что уже реализовано

### Telegram-бот для отчётов мастеров

Реализовано:

- запуск бота через команду `/start`
- кнопка «Новый отчёт»
- инструкция по отправке отчёта
- открытие активной сессии мастера
- приём фотографий
- приём подписи к альбому
- сохранение частей Telegram-альбома
- сборка альбома после периода тишины
- проверка текста отчёта
- определение недостающих данных
- дополнение неполного отчёта
- сохранение отчёта со статусом `incomplete`, если мастер не может уточнить данные
- закрытие сессии после завершения отчёта
- подтверждение мастеру о сохранении отчёта

---

## Техническая база

В пилотной версии используются Data Tables n8n:

- `tg_report_sessions_pilot`
- `tg_report_parts_pilot`
- `tg_reports_pilot`

Они хранят:

- активные сессии мастеров
- отдельные части Telegram-альбомов
- готовые собранные отчёты
- статусы проверки
- недостающие данные
- Telegram file ID фотографий

---

## Google Sheets

Реализована выгрузка полных отчётов в Google Sheets

Текущая таблица:

`БОГЕЛИКА | Отчёты мастеров — PILOT`

Текущий лист:

`Все отчёты`

В таблицу передаются:

- дата создания
- дата обновления
- статус
- студия
- мастер
- клиент
- количество фотографий
- текст отчёта
- недостающие данные
- время выполнения
- `report_key`
- `chat_id`
- `user_id`
- Telegram file ID фотографий

---

## Текущая проблема

Экспорт в Google Sheets пока зависит от конкретного выполнения workflow

Если Google Sheets или сервер временно недоступен, отчёт остаётся в `tg_reports_pilot`, но может не попасть в Google Sheets автоматически

Нужно реализовать отдельный надёжный workflow экспорта с повторными попытками и защитой от дублей по `report_key`
